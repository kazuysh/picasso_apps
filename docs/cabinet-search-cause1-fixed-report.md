# 筐体検索不具合 原因1 修正レポート

## ステータス

**修正済み**

## 対象事象

筐体情報編集画面で材質、塗装色、寸法などの検索条件を変更して保存した後、「回路・配置生成」を実行しても、変更後の条件による筐体検索が行われず、以前に選定された筐体が引き続き使用される。

## 原因

筐体情報の保存処理は `input.cabinfo` のみを更新し、以前の筐体選定結果である次のデータを保持していた。

- `layout.box`
- `layout.boxcode`
- `layout.svg`

回路・配置生成の `ensureBoxSelected()` は、`layout.box` または `layout.boxcode` から箱コードを取得できる場合、「箱選定済み」と判断して筐体検索APIの呼び出しを省略する。

このため、筐体情報が正しく保存されていても、既存の筐体が選定済みの案件では新しい検索条件が評価されなかった。

## 修正内容

筐体情報を保存するとき、`input.cabinfo` の更新と同時に以前の筐体選定結果を無効化するように変更した。

無効化する項目は次のとおり。

| 項目 | 保存後の値 | 目的 |
| --- | --- | --- |
| `layout.box` | `{}` | 選定済み筐体を解除する |
| `layout.boxcode` | `""` | 選定済み判定に使用される箱コードを解除する |
| `layout.svg` | `""` | 以前の筐体を使って生成されたSVGを表示しない |

これにより、次回の回路・配置生成では `ensureBoxSelected()` が選定済み分岐に入らず、現在の `input.cabinfo` を使って筐体検索APIを実行する。

## 変更箇所

- `src/pages/ProjectDetailPage.tsx`
  - `handleSaveCabinetInfo()`

## 修正後の処理フロー

1. 筐体情報編集画面で検索条件を変更する。
2. 「保存」を押す。
3. `input.cabinfo` に変更内容を保存する。
4. 以前の `layout.box`、`layout.boxcode`、`layout.svg` をクリアする。
5. 「回路・配置生成」を実行する。
6. `ensureBoxSelected()` が現在の筐体情報から検索フィルターを生成する。
7. `POST /api/postAnyCollByPage` を呼び出し、新しい条件で筐体を選定する。

## 確認結果

- Vite本番ビルド成功

本番ビルドではチャンクサイズに関する警告が出ているが、本修正に関係するエラーは発生していない。

## 推奨確認手順

1. 筐体が選定済みの案件を開く。
2. 現在の筐体コードを記録する。
3. 筐体情報編集画面で、材質、塗装色、横、縦、深さなどの条件を変更して保存する。
4. 保存直後に以前の筐体選定結果が解除されていることを確認する。
5. 「回路・配置生成」を実行する。
6. 生成ログが「箱選定済み」で終了せず、筐体検索および箱選定を実行することを確認する。
7. 選定された筐体が変更後の条件に一致することを確認する。
